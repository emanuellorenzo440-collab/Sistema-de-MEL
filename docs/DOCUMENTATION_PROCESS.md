# Proceso de Documentacion

## Regla de trabajo

Todo cambio importante debe documentarse. La documentacion debe explicar no solo que se cambio, sino por que existe y como continuar.

## Documentos vivos

- PRODUCT_BRIEF.md: vision, usuarios e intencion del producto.
- BUSINESS_LOGIC.md: reglas, entidades, permisos y flujos de negocio.
- UX_UI_GUIDELINES.md: criterios de experiencia e interfaz.
- RESPONSIVE_STRATEGY.md: reglas para celular, tablet y escritorio.
- ARCHITECTURE.md: capas tecnicas y organizacion del proyecto.
- DECISIONS.md: decisiones importantes y razonamiento.
- WORKLOG.md: historial de pedidos y cambios realizados.
- HANDOFF.md: estado actual, como correr el proyecto y siguientes pasos.

## Como documentar cada pedido

1. Registrar la intencion del usuario en WORKLOG.md.
2. Actualizar reglas de negocio si cambia comportamiento.
3. Actualizar UX/UI si cambia experiencia.
4. Actualizar arquitectura si cambia estructura tecnica.
5. Actualizar handoff si cambia como ejecutar, probar o continuar.

## Fuente de verdad

La conversacion define la intencion. La documentacion convierte esa intencion en especificacion estable del proyecto.
