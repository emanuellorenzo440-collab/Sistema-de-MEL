# UX y UI

## Objetivo de experiencia

El sistema debe sentirse claro, humano, organizado y profesional. Debe ayudar a usuarios no tecnicos a trabajar con datos de monitoreo y evaluacion sin sentirse perdidos.

## Principios UX

- La primera pantalla debe responder: que va bien, que requiere atencion y que falta validar.
- Cada rol debe ver primero lo que necesita para actuar.
- Formularios largos deben estar agrupados y ser faciles de completar.
- Los estados deben ser visibles con lenguaje simple.
- Las graficas deben explicar avance, riesgo y tendencia sin exigir analisis tecnico.
- La app debe evitar pasos innecesarios.
- Las acciones criticas deben confirmar estado con mensajes claros.

## Principios UI

- Interfaz limpia, densa y organizada para trabajo operativo.
- Navegacion consistente entre escritorio y celular.
- Botones primarios solo para acciones principales.
- Tablas con lectura clara y desplazamiento horizontal cuando sea necesario.
- Tarjetas solo para items o paneles funcionales, no decoracion excesiva.
- Colores por significado: avance, alerta, riesgo, neutral e informacion.
- Texto corto y directo, especialmente en celular.

## Experiencia por rol

Facilitador:

- Entrar rapido a reportar.
- Saber si su reporte esta pendiente, aprobado o devuelto.
- Descargar y subir formularios sin confusion.

Coordinador:

- Ver avance del programa.
- Identificar indicadores atrasados.
- Dar seguimiento a acciones.

Supervision M&E:

- Validar reportes pendientes.
- Devolver con razon clara.
- Ver alertas de calidad.

Director:

- Ver resumen ejecutivo.
- Detectar riesgos.
- Entender cumplimiento global y por programa.

## Flujos principales

- Dashboard ejecutivo.
- Crear reporte.
- Descargar formulario.
- Subir formulario completado.
- Revisar graficas.
- Validar reportes.
- Crear o cerrar planes de accion.
- Consultar concept papers.
