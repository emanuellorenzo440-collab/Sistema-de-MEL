# Product Brief

## Vision

Sistema de MEL debe sentirse como una herramienta clara, confiable y facil de usar para equipos de monitoreo, evaluacion y liderazgo. El usuario debe sentir que el sistema le ayuda a ordenar trabajo real de campo, no que le agrega burocracia.

## Intencion del usuario

El usuario expresa como quiere que se sienta y funcione el proyecto. La responsabilidad tecnica del sistema es convertir esa intencion en:

- Logica de negocio completa.
- UX y UI completas.
- Arquitectura frontend, backend y base de datos.
- Experiencia responsiva para celular.
- Documentacion continua.
- Handoff para continuidad.

## Principio de trabajo

Cada pedido del usuario debe interpretarse primero como objetivo de experiencia. La implementacion tecnica no queda limitada a la forma literal del pedido si existe una solucion mejor para producto, negocio, usabilidad o escalabilidad.

El sistema debe construirse con paciencia y criterio, priorizando calidad real sobre velocidad superficial. La meta no es terminar rapido; la meta es llegar a un software excelente para las personas que lo usaran.

Cuando exista una decision que pueda mejorar de forma clara la experiencia, la logica del negocio o la mantenibilidad futura, Codex debe proponerla y explicarla con honestidad.

## Usuarios principales

- Facilitador: captura reportes y evidencias.
- Coordinador de programa: revisa avances de su programa.
- Program Manager: valida datos y toma decisiones operativas.
- Supervision M&E: controla calidad, consistencia y seguimiento.
- Director Nacional: consulta avance ejecutivo, alertas y resultados.

## Resultado esperado

El sistema debe permitir planificar, capturar, validar, visualizar y auditar informacion de programas, indicadores, formularios, concept papers, reportes y planes de accion.
